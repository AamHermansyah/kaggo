info:
  title: Kaggo Backend API
  version: "1.1.0"
  description: |
    Rider-facing REST API for Kaggo (parcel tracking for intercity road
    transport). Consumed by the Flutter mobile app.

    **Identity model**: no signup, login, or OTP. `POST /users/identify`
    resolves a phone number + device IP to a `userId`, which the client
    then sends as the `x-user-id` header on every subsequent request
    that needs "who is asking" - there is no session token; `x-user-id`
    is re-validated against the database on every request, not blindly
    trusted (see `middleware/require-current-user.ts`).

    **Payments are multi-gateway**, not Paystack-only: the gateway used
    for a given shipment is determined by the sender's own resolved
    country (Nigeria -> Paystack, India -> Razorpay). `POST
    /shipments/{id}/pay`'s response shape differs by gateway - see that
    operation's own description.

    **v1.1 update**: `POST /shipments/{id}/pay` and `POST
    /shipments/{id}/verify-payment` now accept either the shipment's
    sender OR receiver (previously sender-only). `GET /shipments` is
    now cursor-paginated. `/batch-tracking/*` (auto-matched batch
    drop-off, previously undocumented) added.

    **Internal-only routes** (`/gps/*`, `/internal/gps/*`,
    `/payments/paystack/webhook`, `/payments/razorpay/webhook`,
    `/shipments/{id}/mark-paid`) are included here for completeness but
    are never called by the mobile app - they're service-to-service
    (gps-server, Paystack, Razorpay) or ops/testing utilities. See each
    operation's description. `/shipments/{id}/mark-paid` is additionally
    disabled entirely (404) whenever the server runs with
    `NODE_ENV=production` - see that operation's own note.

  securitySchemes:
    UserIdHeader:
      type: apiKey
      in: header
      name: x-user-id
      description: >-
        The userId returned by POST /users/identify. Re-validated
        against the database on every request - not a session token.
    InternalApiKey:
      type: apiKey
      in: header
      name: x-internal-api-key
      description: Shared secret for service-to-service calls only. Never used by the mobile app.
    PaystackSignature:
      type: apiKey
      in: header
      name: x-paystack-signature
      description: HMAC-SHA512 of the raw request body using PAYSTACK_SECRET_KEY. Verified, not merely checked for presence.
    RazorpaySignature:
      type: apiKey
      in: header
      name: x-razorpay-signature
      description: >-
        HMAC-SHA256 of the raw request body using
        RAZORPAY_WEBHOOK_SECRET - a SEPARATE secret from
        RAZORPAY_KEY_SECRET, configured independently in the Razorpay
        dashboard. Unlike Paystack, which reuses one secret for both API
        calls and webhook verification.
    GpsWebhookSignature:
      type: apiKey
      in: header
      name: x-kaggo-signature
      description: HMAC-SHA256 of the raw request body using BACKEND_GPS_WEBHOOK_SECRET.
